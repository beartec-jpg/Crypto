Most likely cause of the bug

The trendline click shows no popup because there is no event handling/hit-testing code that:
detects the user clicked near a drawn trendline, and
calls the primitive's setSelected(...) and opens the popup UI.
In short: the primitives know how to draw themselves and how to render selection if setSelected(true) is called, but nothing in the codebase appears to call setSelected on click. Without that bridging code, clicking a line won't produce the selection state or the menu.
Why I think that

chartPrimitives.ts exposes setSelected() but my search did not find any callers of setSelected in the repository.
Radix context-menu/popover is component-based and expects a DOM trigger; drawn primitives live on a canvas (lightweight-charts) and need programmatic control to show a popover — that wiring is missing.

What to implement to fix it (detailed, copy-pasteable guidance)

Add a click handler that maps the mouse click to pixel coordinates and tests distance to every primitive (trendline) drawn. If a primitive is within a threshold (e.g. 6px), mark it selected and open the menu.
Example helper: point-to-segment distance in pixels
ts
function pointSegmentDistance(px: number, py: number, x1: number, y1: number, x2: number, y2: number) {
  const A = px - x1;
  const B = py - y1;
  const C = x2 - x1;
  const D = y2 - y1;
  const dot = A * C + B * D;
  const len_sq = C * C + D * D;
  let param = len_sq !== 0 ? dot / len_sq : -1;
  let xx, yy;
  if (param < 0) {
    xx = x1;
    yy = y1;
  } else if (param > 1) {
    xx = x2;
    yy = y2;
  } else {
    xx = x1 + param * C;
    yy = y1 + param * D;
  }
  const dx = px - xx;
  const dy = py - yy;
  return Math.sqrt(dx * dx + dy * dy);
}
Where to attach the click listener
In the component that creates/owns the lightweight-charts chart instance (the "chart wrapper" component — I did not find an exact file name in the repo search results; look for the component that calls createChart / chart.addSeries or that registers primitives). Add a DOM click listener on the chart container or subscribe via the chart API if available.

Example pattern (pseudo-TSX; adapt to your chart wrapper file):

TSX
// state to control menu
const [menuOpen, setMenuOpen] = useState(false);
const [menuPos, setMenuPos] = useState<{x:number,y:number}|null>(null);
const primitives = useRef<DrawingPrimitive[]>([]); // populate this when you create primitives

useEffect(() => {
  const handler = (e: MouseEvent) => {
    const rect = chartContainerRef.current!.getBoundingClientRect();
    const px = e.clientX - rect.left;
    const py = e.clientY - rect.top;

    // loop primitives and test
    let clickedPrimitive: DrawingPrimitive | null = null;
    for (const p of primitives.current) {
      const pts = p.getPoints();
      if (pts.length < 2) continue;
      const x1 = chart.timeScale().timeToCoordinate(pts[0].time as any);
      const y1 = series.priceToCoordinate(pts[0].price);
      const x2 = chart.timeScale().timeToCoordinate(pts[1].time as any);
      const y2 = series.priceToCoordinate(pts[1].price);
      if (x1 == null || x2 == null || y1 == null || y2 == null) continue;
      const dist = pointSegmentDistance(px, py, x1, y1, x2, y2);
      if (dist < 6) { clickedPrimitive = p; break; }
    }

    // clear selection for all
    primitives.current.forEach(p => p.setSelected(false));

    if (clickedPrimitive) {
      clickedPrimitive.setSelected(true);
      setMenuPos({ x: e.clientX, y: e.clientY });
      setMenuOpen(true);
    } else {
      setMenuOpen(false);
      setMenuPos(null);
    }
  };

  const container = chartContainerRef.current;
  container?.addEventListener('click', handler);
  return () => container?.removeEventListener('click', handler);
}, [chart, series]);
Notes:

Use pixel coordinates relative to the chart drawing area (offset or rect-based).
Use a small threshold (4–8 px) to account for user imprecision and line thickness.
When setting selection, call setSelected on the matching primitive; setSelected calls requestUpdate and the renderer will draw selection handles.
Showing the popup menu
Because your drawn primitives are canvas/SVG based, Radix ContextMenu triggers (which wrap DOM items) won't work directly. Show the menu programmatically using absolute/fixed positioned Popover/Portal or a custom div positioned at the clicked screen coordinates.

Example (very small) menu render:

TSX
{menuOpen && menuPos && (
  <div style={{
    position: 'fixed',
    left: menuPos.x,
    top: menuPos.y,
    zIndex: 9999
  }}>
    <div className="bg-slate-800 text-white rounded shadow p-2">
      <button onClick={() => {/* edit action */}}>Edit</button>
      <button onClick={() => {/* delete action */}}>Delete</button>
    </div>
  </div>
)}
Or adapt the Radix Popover to be controlled and anchored at the screen coords (render PopoverContent in a Portal at that position).
Additional checks / possible edge-cases
Make sure you are iterating the same primitive instances that were registered with the chart (not clones). If you create primitives and register them with the chart, keep a reference array of those instances for hit-testing.
If your chart wrapper overlays other DOM elements over the chart (toolbars, overlays), ensure the click events reach the chart container (pointer-events not blocked).
If you use multiple panes or multiple series, make sure you use the correct series and chart references when calling priceToCoordinate/timeToCoordinate.
If you need right-click context-menu behavior, capture contextmenu events (preventDefault) and use the same hit-test logic.
Quick debugging steps to confirm the root cause

Add a console.log in the chart click handler (or add one temporarily by adding a DOM click listener) and log the mouse coords and number of primitives iterated — verify it fires.
Temporarily always call the first primitive.setSelected(true) on any click to confirm selection visuals appear (this verifies rendering path works).
If selection visuals appear but menu still doesn't, the issue is only menu positioning or display (z-index / portal / pointer-events).
If selection never appears even after calling setSelected, verify the primitive instance is attached to the chart (attached() called), and that the primitive.requestUpdate callback was set when attached (the primitive uses requestUpdate to redraw).
